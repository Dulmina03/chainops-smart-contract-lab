# Team lesson checkpoints

Use this table in team sessions; the evidence belongs in each individual's fork.

| Session | Verify live | Explain in words |
|---|---|---|
| 00 | Fork, clone, remotes and empty `voting-lab/` | Why fork rather than shared generated scaffold? |
| 01 | Draw Solidity → EVM → RPC model | ABI, bytecode, receipt, event |
| 02 | `hardhat build` and `hardhat test` | Build vs test; where artifacts come from |
| 03 | Passing and intentionally failing voting tests | Revert, state, event |
| 04 | Local node, Ignition deployment, vote receipt | Network, transaction hash, address |
| 05 | Sepolia tx in explorer (if accessible) | RPC provider, test ETH, confirmations |
| 06 | Static scan output and decoded event | Analyzer vs policy; event vs alert |
| 07 | Explain linked ChainOps lifecycle | Commit → artifact → approval → deployment → monitor |

**Policy:** If an external service is unavailable (e.g. Sepolia faucet), record that honestly; do not fake evidence. Continue local EVM learning.
